libtooling-wrapper is a C++20 module wrapper generated by the modulizer tool
(`--wrapper` mode). It re-exports clang/llvm declarations via
`using ::clang::...;` / `using ::llvm::...;` so that downstream C++20-module
projects can `import libtooling;`.

It is three modules rather than one, because a using-declaration may only name
an entity with external linkage and some of what these headers declare has
none — a namespace-scope `const` is internal unless it is `inline` or `extern`,
and an unnamed enum has no name for its enumerators to take linkage from.
Those constants are published as values instead:

  * `libtooling_main.cc` (`libtooling.main`) — the using-declarations.
  * `libtooling_constants.cc` (`libtooling.constants`) — copies of the
    constants nothing can name, under a private namespace. This unit includes
    the headers, so it cannot publish `clang::X` itself: that name is already
    taken here.
  * `libtooling.cc` (`libtooling`) — the facade. It includes no header, which
    is what leaves those names free, and declares them from the copies.

Consumers import `libtooling` and see one API; the other two are an
implementation detail of how it is assembled.

file in this directory, which is the LLVM Project license). The wrapper

When consuming this package via CPM.cmake:

    CPMAddPackage(NAME libtooling-wrapper
      GIT_REPOSITORY https://github.com/j4niwzis/libtooling-wrapper.git
      GIT_TAG main
      GIT_SHALLOW TRUE)

    target_link_libraries(your_target PRIVATE libtooling)

    // your_target source
    import libtooling;
